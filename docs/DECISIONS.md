# Decisions

## 2026-10-23 · mls-ds conversation Spaces · Persist immutable creation-time placement

Chose: creation-time `mlsds` or `space` placement with a UUID generation, with existing conversations backfilled to `mlsds` (provisional). Because: existing histories must not silently move, and a deleted Space must not create a second conversation history under the same identity. The configured hosted authority requires an explicit issuer-readiness acknowledgement before new Space placements can be created. Rejected: choosing storage per write or silently falling back when the configured service is unavailable.
Reversible until: merge of the Space release bookmark; production migration remains separately authorized. Override by: changing the creation initializer and migration together before deployment. Governing implementation and verification boundaries: [Conversation Space storage](SPACE_CONVERSATION_STORAGE.md).

## 2026-10-23 · mls-ds conversation Spaces · Reuse retained batch metadata and deny unsupported policy cases

Chose: store ciphertext-free batch metadata plus immutable source reference/CID in the existing retention tables, preserving signed tombstones, per-MEK read authorization, attachment invalidation and deletion outbox (provisional). Because: a separate reference table would bypass established retention paths unless every consumer were rewritten. A database trigger independently forbids retaining ciphertext in Space rows. Rejected: copying ciphertext into both stores or assuming remote/pending-request membership implies a Space credential grant.
Reversible until: merge of the Space release bookmark. Override by: implementing equivalent retention and lifecycle invariants in a separate reference table before merge. Mixed-host and pending-participant Space operations fail explicitly until their authority lifecycle is implemented.

## 2026-10-23 · mls-ds and Swan · Use authority service authentication for live credential policy

Chose: Swan derives the user DID from canonical Space delegation and queries `getSpaceMembership(space,user)` with a short-lived authority service JWT (provisional). Because: the canonical credential request has no field for a separate Labyrinth device-proof transcript. The DS binds the authority, exact immutable Space generation, accepted member and current registered leaf to committed state; the response is not cacheable. Rejected: adding noncanonical credential fields, DID-only readiness, or using a stale issuer-owned member list for conversation Spaces.
Reversible until: merge of the Space release bookmark. Override by: coordinating the authority lookup schema and Swan policy adapter before merge. This policy permits encrypted-byte access; MLS decryption and exact device-bound archive admission remain separate.

## 2026-10-23 · mls-ds and Swan · Commit terminal DS generation before authority deletion success

Chose: authority-authenticated `deleteSpaceGeneration` with exact immutable Space/generation binding, preceded by Swan's durable pending-deletion state and followed by durable standard notifications to registered PDS recipients (provisional). Because: stopping new grants alone leaves existing credentials usable, and a callback after successful local deletion can leave the DS serving a supposedly deleted generation during failures. The DS transition is idempotent with a fresh service JWT and also prevents attachment liveness from surviving a deleted Space. Rejected: in-memory callbacks, implicit generation replacement, and reporting success before DS termination and durable notification fanout.
Reversible until: merge of the Space release bookmark. Override by: coordinating both authority and DS lifecycle transactions and their retry tests before merge. This is local implementation work; deploying the new lifecycle and provisioning a real authority remain separate operator actions.

## 2026-10-23 · mls-ds service authentication · Decode declared legacy secp256k1 keys explicitly

Chose: support the AT Protocol legacy `EcdsaSecp256k1VerificationKey2019` representation only when explicitly declared, with base58btc of a 65-byte uncompressed SEC1 point and normal secp256k1 signature verification (provisional). Because: the actual local PLC document uses this documented legacy format; the previous server incorrectly required a Multikey codec prefix for every multibase field. The ES256K branch also requires the resolved document, controller and selected `#atproto` method to belong to the exact issuer. Multikey and JWK remain separate declared encodings; malformed/ambiguous encodings cannot fall back into the legacy path. Rejected: rewriting real DID documents in the smoke fixture, accepting raw points after any codec error, or weakening signature verification.
Reversible until: merge of the Space release bookmark. Override by: removing the explicit legacy decoder and retaining the qualified interoperability failure. Authoritative format: [AT Protocol DID legacy representation](https://atproto.com/specs/did#legacy-representation); implementation and evidence are in [the verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md). No production authentication configuration was changed.

## 2026-10-23 · mls-ds service authentication · Decode declared legacy P-256 authority keys explicitly

Chose: extend the P-256 decoder with the documented `EcdsaSecp256r1VerificationKey2019` representation, requiring base58btc of a 65-byte uncompressed SEC1 point and normal P-256 curve/signature validation (provisional). Because: the actual Swan authority publishes that format and its otherwise valid ES256 service token was rejected before the conversation-membership policy could run. The ES256 JWT branch now binds the document, controller and selected relative or exact issuer-absolute `#atproto` method to its canonical issuer. The shared key extractor validates declared encoding/curve only; caller-specific authorization stays with callers. JWK and Multikey remain explicit, separate encodings and ambiguous fields fail closed. Rejected: altering the real public DID document, trying raw-point fallback after codec failure, or weakening signature/endpoint/nonce checks.
Reversible until: merge of the Space release bookmark. Override by: reverting this successor's explicit P-256 decoder and retaining the qualified Swan interoperability failure. Format authority: [AT Protocol legacy DID representation](https://atproto.com/specs/did#legacy-representation); evidence and qualification limits are in [the verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md). No production authentication configuration was changed.

## 2026-10-23 · mls-ds CI · Bound inherited formatting debt and vendor the frozen test input

Chose: require changed-line formatting and reject every new formatting hunk on pull requests, using the actual PR base plus fixed reviewed bootstrap `c402df68efe98962db4f16e3bcd3f218776bc49d`; retain the complete full-repository rustfmt failure as an artifact, with strict whole-repository enforcement on push/dispatch (provisional). Because: inherited formatting debt blocks tests before they execute, while mass formatting would rewrite source bytes already bound to the runtime receipt. Exact raw/formatted hunk matching with bounded multiplicity prevents context changes from introducing hidden debt. Also vendor the unchanged first frozen application vector, with the original manifest hash, so CI no longer depends on an absent encompassing-workspace file. Rejected: disabling rustfmt entirely, accepting arbitrary user-selected debt baselines, altering frozen expected values, or reformatting authenticated-runtime source during CI repair.
Reversible until: merge of the Space release bookmark. Override by: retiring the fixed bootstrap after a separately reviewed full formatting change, or replacing the vendored test input with a versioned artifact dependency preserving the same bytes. See [the verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md) for failed and passing checks. Production rollback is additionally gated to an actual explicitly dispatched deployment attempt; this code change performs no production action.

## 2026-10-23 · mls-ds message routing · Restrict direct-request transport to persisted direct conversations

Chose: read the committed conversation kind before post-commit application-entry delivery; groups use their existing transactional federation outbox, and only direct conversations enter the accepted direct-request transport (provisional). Because: hosted federation run 40056388899 admitted a group message and then returned HTTP 500 while unnecessarily resolving a direct pair. Adding actor DID/PDS fixtures would only advance to the direct transport's entitlement rejection, because group members do not have accepted direct-request inbox rows. The shared delivery helper applies the same rule to initial sends and idempotent replay. Missing or unknown persisted kinds fail as invariants, and database errors remain failures. Rejected: bypassing authoritative DID/PDS resolution, weakening direct-device entitlements, defaulting unknown state to group, or masking the production routing defect with test-only fallback.
Reversible until: merge of the Space release bookmark. Override by: restoring unconditional pair delivery and retaining the concrete failed federation result, or implementing a separately reviewed unified transport that preserves both authorization models. Governing plan: workspace `docs/research/2026-10-23-spaces-release-readiness.md`; retained failure: [terminal hosted report](../../artifacts/server-ci-006e-report.md). This correction creates a new runtime identity and requires fresh affected handler, federation and native Swan/storage verification; the earlier `812e5c5` runtime receipts remain historical evidence only.

## 2026-10-25 · mls-ds message routing · Reject local sends on remote group replicas

Chose: fail closed with the existing `NotAuthorized` sendMessage error when the locked conversation is both a group and a remote replica, before message mutation; require the same persisted distinction in post-commit/replay delivery (provisional). Because: only the local sequencing authority queues the ordinary federation outbox. A remote group row previously admitted local messages without that outbox, and skipping pair transport for groups would otherwise report a successful unforwarded send. Direct-conversation transport remains unchanged. Rejected: inventing a forwarding protocol, treating a replica as the sequencing authority, or returning success with no delivery path.
Reversible until: merge of the Space release bookmark. Override by: replacing this bounded rejection with an independently reviewed authenticated forwarding/sequencing protocol and matching replay guarantees. Governing plan: workspace `docs/execution-plans/2026-10-23-spaces-release-implementation.md`; [verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md) distinguishes no-mutation rejection from successful remote group delivery. No production service or database was changed.

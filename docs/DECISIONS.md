# Decisions

## 2026-10-23 · mls-ds conversation Spaces · Persist immutable creation-time placement

Chose: creation-time `mlsds` or `space` placement with a UUID generation, with existing conversations backfilled to `mlsds` (provisional). Because: existing histories must not silently move, and a deleted Space must not create a second conversation history under the same identity. The configured hosted authority requires an explicit issuer-readiness acknowledgement before new Space placements can be created. Rejected: choosing storage per write or silently falling back when the configured service is unavailable.
Reversible until: merge of the Space release bookmark; production migration remains separately authorized. Override by: changing the creation initializer and migration together before deployment. Governing implementation and verification boundaries: [Conversation Space storage](SPACE_CONVERSATION_STORAGE.md).
Superseded 2026-10-31 by the clean-slate consolidation: migration `20261031200001_clean_slate_spaces_only.sql` dropped `labyrinth.thread_storage`; each conversation generation now registers one Space in `chat.conversation_spaces`, with the sequencing DS as its authority ([current contract](SPACE_CONVERSATION_STORAGE.md)).

## 2026-10-23 · mls-ds conversation Spaces · Reuse retained batch metadata and deny unsupported policy cases

Chose: store ciphertext-free batch metadata plus immutable source reference/CID in the existing retention tables, preserving signed tombstones, per-MEK read authorization, attachment invalidation and deletion outbox (provisional). Because: a separate reference table would bypass established retention paths unless every consumer were rewritten. A database trigger independently forbids retaining ciphertext in Space rows. Rejected: copying ciphertext into both stores or assuming remote/pending-request membership implies a Space credential grant.
Reversible until: merge of the Space release bookmark. Override by: implementing equivalent retention and lifecycle invariants in a separate reference table before merge. Mixed-host and pending-participant Space operations fail explicitly until their authority lifecycle is implemented.
Superseded 2026-10-31: migration `20261031200001` dropped `labyrinth.batches` and `labyrinth.batch_items`; the DS keeps no Space batch metadata, and clients on other homes reach a conversation's Space through `relaySpaceCredential` and `relaySpaceRead`.

## 2026-10-23 · mls-ds and Swan · Use authority service authentication for live credential policy

Chose: Swan derives the user DID from canonical Space delegation and queries `getSpaceMembership(space,user)` with a short-lived authority service JWT (provisional). Because: the canonical credential request has no field for a separate Labyrinth device-proof transcript. The DS binds the authority, exact immutable Space generation, accepted member and current registered leaf to committed state; the response is not cacheable. Rejected: adding noncanonical credential fields, DID-only readiness, or using a stale issuer-owned member list for conversation Spaces.
Reversible until: merge of the Space release bookmark. Override by: coordinating the authority lookup schema and Swan policy adapter before merge. This policy permits encrypted-byte access; MLS decryption and exact device-bound archive admission remain separate.
Superseded 2026-10-31: `getSpaceMembership` is no longer mounted; the sequencing DS is itself the Space authority and issues credentials through `com.atproto.space.getSpaceCredential`.

## 2026-10-23 · mls-ds and Swan · Commit terminal DS generation before authority deletion success

Chose: authority-authenticated `deleteSpaceGeneration` with exact immutable Space/generation binding, preceded by Swan's durable pending-deletion state and followed by durable standard notifications to registered PDS recipients (provisional). Because: stopping new grants alone leaves existing credentials usable, and a callback after successful local deletion can leave the DS serving a supposedly deleted generation during failures. The DS transition is idempotent with a fresh service JWT and also prevents attachment liveness from surviving a deleted Space. Rejected: in-memory callbacks, implicit generation replacement, and reporting success before DS termination and durable notification fanout.
Reversible until: merge of the Space release bookmark. Override by: coordinating both authority and DS lifecycle transactions and their retry tests before merge. This is local implementation work; deploying the new lifecycle and provisioning a real authority remain separate operator actions.
Superseded 2026-10-31: `deleteSpaceGeneration` is no longer mounted; closing a conversation wipes its Space rows and sends `notifySpaceDeleted` after commit.

## 2026-10-23 · mls-ds service authentication · Decode declared legacy secp256k1 keys explicitly

Chose: support the AT Protocol legacy `EcdsaSecp256k1VerificationKey2019` representation only when explicitly declared, with base58btc of a 65-byte uncompressed SEC1 point and normal secp256k1 signature verification (provisional). Because: the actual local PLC document uses this documented legacy format; the previous server incorrectly required a Multikey codec prefix for every multibase field. The ES256K branch also requires the resolved document, controller and selected `#atproto` method to belong to the exact issuer. Multikey and JWK remain separate declared encodings; malformed/ambiguous encodings cannot fall back into the legacy path. Rejected: rewriting real DID documents in the smoke fixture, accepting raw points after any codec error, or weakening signature verification.
Reversible until: merge of the Space release bookmark. Override by: removing the explicit legacy decoder and retaining the qualified interoperability failure. Authoritative format: [AT Protocol DID legacy representation](https://atproto.com/specs/did#legacy-representation); implementation and evidence are in [the verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md). No production authentication configuration was changed.

The shared key extractor validates declared encoding/curve only; caller-specific authorization stays with callers. JWK and Multikey remain explicit, separate encodings and ambiguous fields fail closed. Rejected: altering the real public DID document, trying raw-point fallback after codec failure, or weakening signature/endpoint/nonce checks.
Reversible until: merge of the Space release bookmark. Override by: reverting this successor's explicit P-256 decoder and retaining the qualified Swan interoperability failure. Format authority: [AT Protocol legacy DID representation](https://atproto.com/specs/did#legacy-representation); evidence and qualification limits are in [the verification report](SPACE_CONVERSATION_STORAGE_VERIFICATION.md). No production authentication configuration was changed.

## 2026-11-04 · mls-ds direct requests · Answer every transient direct-request failure with the retryable `CapacityUnavailable`

Chose: a direct-request failure that decided nothing is the already-declared `CapacityUnavailable` with `Retry-After: 5`, records no signed receipt and leaves retry-safe state (provisional). It covers: a sender home that cannot reach the pair's remote coordinator for `prepareDirectRequest`, `publishDirectRequest` or `getDirectRequestOutcome` (closed federation gate, connect or timeout, 5xx, 429, including resolving the coordinator); a recipient declaration, chat-authority, PDS device-key or relationship-policy source that cannot answer now (`AuthorityError::Unavailable`/`Capacity`, a transient DID-document or declaration fetch, which now reaches the policy as `RelationshipRepositoryError::Unavailable` → `DirectRequestStoreError::Unavailable`); and a coordinator whose reservation relay to the recipient's home cannot reach it. Only an authoritative answer is durable: a malformed declaration or a DID document that is not found (404) or tombstoned (410) stays the signed `RequestPolicyDenied`, a declared foreign authority stays `RecipientAuthorityUnsupported`, and the home's own refusal or a PDS that authorizes no device key stays `RecipientKeysUnavailable`. A database failure inside the policy check is a storage failure rather than a durable refusal. Retry safety: the coordinator keeps its pending `direct_request_reservation_intents` row and the recipient home's idempotent lease on any transient failure (it releases only on a terminal outcome or refusal), so the identical signed request resumes the same reservation and key package; a coordinator answering a sender home over S2S returns 503 for these failures so the sender home classifies them the same way. Prepare withdraws the outbound route it recorded only when it inserted the route and the row version (`xmin`) it wrote is unchanged, under the pair lock: an identical concurrent prepare rewrites the row before relaying, so a successful concurrent result is never withdrawn. Publish records its route only after the coordinator answers. Because: every such failure previously became a durable `RequestPolicyDenied`/`RecipientKeysUnavailable` or a released reservation that the identical retry could never resume, although nothing was decided. Both Lexicons already declare `CapacityUnavailable`, which group relays and `closeConversation` use with the same 5-second hint, so no Lexicon or generated binding changes. Rejected: a new retryable error code (Lexicon, binding and client churn for a meaning that already exists); holding the route transaction or a pool connection across the relay (the pair lock held over network I/O); and a schema column for the route claim, since the row version already scopes the claim to the attempt that wrote it.
Route answers (`20261104000011_direct_request_route_answers.sql`): a sender home records each outbound route with `binding_expires_at`, derived from the signed prepare it authenticated: `signedAt` plus the 300 s a coordinator still admits it (`require_fresh_at`) plus the 300 s preparation lease, the latest instant any preparation made from those bytes could be live. An identical retry never changes it. The home marks the route `answered_at` and clears `binding_expires_at` (NULL: binds permanently) when the pair coordinator answers its prepare relay, or the relay fails for a reason no retry cures; publish records its route already answered, and a check constraint keeps exactly one of the two set. Existing routes were backfilled as answered, so none is left unanswered. An answered route binds its pair as before; an unanswered one binds it only while `now < binding_expires_at`, so a recipient that moves its home, and with it the pair's coordinator, is not pinned to a coordinator that answered nothing. The expiry worker's cycle deletes an unanswered route an hour after it was recorded, never touching an answered route or any receipt, inbox or idempotency row. The row version still scopes the route claim; `answered_at` records the answer, not the claim. Rejected: a window from `created_at`, which a later recording or a slow first relay would shift away from what the signed bytes allow.
Reversible until: merge of the Space release bookmark. Override by: declaring a dedicated retryable code in both Lexicons and regenerating the bindings. Regressions: `direct_request_relay_tests.rs` (`an_unreachable_pair_coordinator_is_retryable_and_commits_nothing`, `a_failed_identical_prepare_never_withdraws_an_answered_route`, `a_policy_source_that_cannot_answer_decides_nothing_at_the_coordinator`, `a_lost_reservation_answer_resumes_the_same_lease_on_the_identical_retry`, `a_leftover_route_holds_one_slot_until_it_ages_out_of_the_hourly_quota`, `a_leftover_route_binds_its_pair_only_while_its_preparation_could_be_live`, `the_sweep_deletes_only_routes_left_unanswered_for_an_hour`), `handlers/chat/expiry_worker.rs` (`one_cycle_deletes_only_routes_left_unanswered_for_an_hour`) and `handlers/chat/direct_requests.rs` (`unresolved_recipient_is_refused_only_by_its_own_declaration`). A route left by identical prepares that all failed stays unanswered: the identical retry reuses it without moving its deadline, it binds its pair until that deadline, it stops counting toward the hourly quota an hour after it was recorded, and the expiry worker then deletes it. catbird-mls classifies the same responses (`CapacityUnavailable`, 429, 500/502/503/504 retryable with a bounded delta-seconds `Retry-After`, or a persisted 5-second default for `CapacityUnavailable` where its gateway exposes no headers; semantic 4xx terminal), retries the identical journaled request, and verifies a signed terminal receipt before dropping its journal.

## 2026-11-08 · mls-ds Space authority · Sign membership refusals and relay them byte for byte

Chose: when `com.atproto.space.getSpaceCredential` refuses a requester that is not an active member, the Space authority answers 403 `NotAuthorized` (declared by both that lexicon and `blue.catbird.chat.relaySpaceCredential`; it was the undeclared `Forbidden`) with a `denial` field: a compact ES256 JWS under the authority's `#atproto` key, the key that signs its credentials (provisional). Header: exactly `{"alg":"ES256","typ":"catbird-space-denial+jwt","kid":"#atproto"}`. Claims: `iss` (the authority DID), `sub` (the Space URI), `aud` (the requester account, the delegation token's issuer), `iat`, `exp` = `iat` + 60, `jti`, `cnf.kid` (the request's fresh proof-of-possession key), `conversationId`, `generation`, `groupId` (lowercase hex MLS group of that generation) and `reason` = `notActiveMember`. A home's `relaySpaceCredential` forwards a 403 whose body is `NotAuthorized` with a string `denial` byte for byte (status, `application/json`, body); every other refusal stays the relay's own unsigned `NotAuthorized`. catbird-mls accepts a conversation-Space refusal as removal proof only after it verifies the signature under the `#atproto` method of exactly the Space's authority DID (resolved through the account PDS, one refresh, as for credentials) and every binding: Space, `{conversationId}-{generation}` equal to the Space key, the MLS group its restore pinned (local roster or newest signed owner receipt), this account, this request's PoP key, the reason, and a live window of at most 60 s. Anything else, including any unsigned read refusal, leaves the restore `ArchiveRestorePending`. Same-home and cross-home are identical: the client no longer trusts a refusal because its home DS is the authority.
Because: the R4 tank (`task-4-gate-logs/sim-r4-final-85d25801-4802d500/divergence-o6-archive-restore-pending/`, 21/33 forward seeds) left every cross-home kicked member's fresh-device restore pending forever: the authority's 403 reached the client only as the relaying home's unsigned answer, and `D1` bars contacting the authority directly. The bound `groupId` also closes R3 client finding #8: owner receipts sign the group but not the generation that names the Space, so a denial of a Space named by a wrong generation never matches the pin. The fresh `cnf.kid` makes a captured denial useless for any later request.
Rejected: the `I13` receipt key, because every Space-host embedder (production `main.rs`, fixtures, catbird-sim) holds only the Space key, and sequencing attestations stay separate from Space access. Retained key history, because a denial lives 60 s: a key rotation inside that window yields a retryable pending restore, not a wrong answer. A new lexicon error, because both lexicons already declare `NotAuthorized` and an XRPC error body's extra field needs no binding regeneration.
Reversible until: merge of `clean-slate-2026-10-31`. Override by: returning unsigned refusals and reinstating the client's same-home trust, which restores the cross-home pending restore. Regressions: `tests/space_host_and_revocation.rs` (the removed member's signed denial), `handlers/chat/space_relay.rs` `signed_authority_refusals_cross_the_credential_relay_byte_for_byte`; catbird-mls `native_space_auth_accepts_only_the_authoritys_signed_refusal_as_space_denial` and `fresh_removed_restore_requires_owner_proof_and_authenticated_space_denial`.
